# 火の鳥「A問題」

## 問題提起

人間には字形の中に通常の「A」を読み取れるのに、画像モデルがその基底字形を候補として回収できない。この、人間の視覚的理解とモデルの字形理解の隔たりを、火の鳥の「A問題」と定義する。代表例は通常の A と二重線の装飾を持つ 𝔸 である。

これは単なる画素一致率の調整課題ではない。モデルが装飾や書体差を含む画像から字形の共有構造を取り出し、元の記号表記を保ったまま基底文字との関係を提示できるかという、記号画像理解上の課題である。

## 規格上の根拠と注意

Unicode は 𝔸（U+1D538）を MATHEMATICAL DOUBLE-STRUCK CAPITAL A と定義し、数学用英数字記号には基底となるラテン文字・ギリシャ文字への互換分解を定めている。これは「𝔸の基底文字はA」という教師信号の根拠になる。一方、Unicode数学記号規格は、書体差を単純に正規化で消すと数学上の意味の区別が失われる場合があると明記している。したがって、Aと𝔸を同じ文字コード・同じ記号へ潰してはならない。

火の鳥では、記号同一性（入力が𝔸であること）と、基底字形・共有部分（Aを含むこと）を別々の出力として保持する。類似部分集合への同居は候補関係を示し、Unicode上の同一性や数式上の意味が同じだとは主張しない。

## 観測済みの失敗

- Mac字形コーパスでは、通常の A は214フォントファイルにあり、𝔸は1フォントファイルにある。両方を同じフォントファイルから得られる対も1件あるため、「画像が存在しない」は原因ではない。
- 現行の全フォント集合出力では、A（語彙行26）と𝔸（語彙行122）がともに単独集合になり、A–𝔸候補を回収できていない。
- 同一フォントの一対に対する旧骨格特徴の共有率は19.3%。同じ骨格を粗い格子へ縮約した画素重なりは、2×2で9.7%、4×4で33.9%、8×8で68.8%だった。結果は尺度と表現に大きく依存し、単一の画素閾値を意味上の正解とみなせない。
- cycle630のペアViT拡張版は、同じ3,916件の検証ペアを用いたcycle628基準版に対して、macro MAEが0.04843から0.06210へ悪化し、macro balanced accuracyが88.08%から74.47%へ悪化した。今回のデータ拡張はA問題を解決しておらず、改善として採用しない。
- cycle630の集合生成結果でも、Aと𝔸は候補なしの単独行だった。これは機械生成ラスタ教師に対する結果で、人間の共有構造判断を測った結果ではない。

## 調査で見つかった要素技術

既製の「A問題専用モデル」は確認できませんでした。一方、次の要素技術には一次資料上の根拠があり、組み合わせて検証できます。

| 要素技術 | A問題での役割 | 根拠と適用範囲 |
|---|---|---|
| Unicode互換分解を使った基底字教師 | 𝔸に基底文字Aの教師ラベルを与える。元のコードポイント𝔸は別出力で維持する | Unicode数学用英数字は基底ラテン・ギリシャ文字への互換分解を持つ。ただしUnicodeは、意味が変わるためこの区別を常に正規化で消すべきではないと明記している。教師信号として使い、推論結果をNFKCで置換しない |
| 視覚照合型の文字認識 | 固定229クラスの最終分類だけに頼らず、入力字形と記号見本を比較する | Oxford VGGのECCV 2020方式は字形見本との視覚類似マップから未見フォント・新規文字へ一般化する構成を報告している。ただし文章行の認識方式なので、そのまま火の鳥の孤立字形用に使えるとの証拠ではない |
| 字形の中心軸・輪郭・部品分解 | Aの斜線2本と横棒、それらの接続構造を検出し、𝔸の二重線装飾と分ける | StrokeStylesはフォント輪郭、内部・外部medial axis、凹凸特徴、接合構造から字形を重なり合うストロークへ分解する。Shape Contextは形状点の対応を使って字形間の類似を測る |
| 基底字形と書体の分離学習 | Aという形の核を保ったまま、二重線・太字などの書体差を別属性として学習する | 教師あり対照学習は同じ教師群を表現空間でまとめ、異なる群を分離する一般技術。火の鳥ではUnicode由来の基底字群をまとめる損失と、正確な記号ID・書体属性を保持する別の出力を組み合わせる設計候補となる。A問題での効果は未検証 |
| 書体・描画条件の制御データ拡張 | 線幅、アンチエイリアス、解像度、ぼかしの変化に対する頑健性を学ぶ | 意味構造を変えないレンダリング変化に限定する。回転・鏡映は正例拡張に使わず、拡張見本を独立フォント数として数えない。前回の拡張実験は全体指標が悪化したため、同じ手法を改善とみなして再採用しない |

## 火の鳥での統合案

入力活字画像から、共有重みの画像エンコーダで「基底字形特徴」と「書体・装飾特徴」を別々に得る。教師は、(1)元の229記号ID、(2)Unicode互換分解から得た基底文字ID、(3)レンダリング書体IDの三系統とする。基底文字IDはA系の装飾変種を結び、元の記号IDはAと𝔸を区別し続ける。書体IDは装飾の差を無視して消すのでなく説明可能な属性として保持する。

画像側では輪郭・中心軸から字形部品グラフを作り、Aの二斜線と横棒の接続関係を𝔸画像内の部分構造と照合する。全体画素IoUや単一の粗解像度閾値を最終判定にせず、視覚埋め込みの照合と構造部品の対応を併用する。これは実装方針の候補であり、成功済みの実装ではない。

## 実証手順

1. Mac字形コーパスから、Aと数学用書体変種のUnicode基底対応を持つ全字形を抽出し、各記号・書体の画像数を監査する。実フォントの独立数と合成拡張数を別に記録する。
2. フォントファイル単位で学習・検証・外側評価を分離する。単一フォントしかない𝔸は、単純なフォント汎化の証拠に使わず、ほかの数学用A書体変種を用いた基底字汎化も併記する。
3. 同一分割で、現行ペアViT、Unicode基底教師付き視覚照合、部品グラフ併用方式を比較する。A–𝔸の回収、基底A候補の適合率、異なる基底字の誤結合、229記号全体の候補なし率を測る。
4. まずA/𝔸の画像・部品対応・各出力を目視監査し、次に全229記号へ適用する。A–𝔸だけを手で集合へ追加して、モデルが解決したと数えてはならない。
5. 学習拡張の有無も同一分割で比較する。macro誤差、balanced accuracy、候補適合率・再現率、フォント別成績のいずれか一つだけの改善で採用せず、誤結合と候補欠落の双方を確認する。

## ミッションと合格条件

火の鳥のミッションは、A問題を解決し、記号画像から「入力記号の識別」と「基底字形・共有部分の候補」を両立して出力できることを、再現可能な評価で実証することである。

1. 通常の A と 𝔸 を、別の記号IDのまま保持し、同じ基底A・共有形状候補として結び付ける。
2. 学習に使っていないフォント・描画条件でもその関係を回収する。現在はAと𝔸の同一フォント対が1件だけなので、これだけでフォント汎化を合格とはしない。
3. A以外の229記号にも同じ構造表現を適用し、不要な共有候補の増加を測る。A–𝔸だけを固定で結んで全体性能が改善したとは扱わない。
4. 画素重なり教師、構造対応方式、現行方式を同じ分割で比較し、A–𝔸の回収率と誤結合率、および全229記号の集合品質を併記する。
5. 人の判定を参照する評価では、判定者・基準・不一致を記録し、機械生成教師の評価と分離する。

これらの実測が完了するまでは、A問題は未解決と記録し、世界最高・完成とは宣言しない。
