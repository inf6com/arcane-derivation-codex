# 記号候補の形状類似・位置関係判定契約（ルールベース・検証前）

内部名称は **Symbol Context Adjudicator（SCA／記号候補文脈判定器）** とする。記号候補の形状類似と位置関係を組み合わせて確認する後段の判定責務を示す名称であり、製品名や利用者向け機能名にはしない。既存コードを名称変更したことは意味しない。

## 目的と境界

記号認識モデルによる推論の後に、モデルが示す形状類似の候補、混同しやすい記号群、手書きパッドの元座標を入力として、記号の候補と位置関係をルールベースで判定する。独立した位置判定用深層学習モデルは作らず、記号認識の学習や重みを置換しない。横線のマイナス・分数線・下線の区別と、上付き・下付き等は局所的な形だけでは確定しない。根拠が不足または競合する場合は候補を残し、利用者が選択する。この判定器だけで数式全体の認識完了を意味しない。

## 類似と位置の契約

- 活字字形類似は、指定フォントで描画した字形間のIoU距離と対称Chamfer距離を別々に測る。手書きモデルの候補・スコア、学習特徴距離とは別の根拠として保持する。
- 活字距離から補助候補を提示する場合はモデル候補と由来を分け、モデルスコア・確率を捏造しない。語彙、字形対応表、フォント、距離指標の版を検証する。未生成の距離資産を暗黙に補完しない。
- 位置関係は元の座標と周囲の候補を用いる。位置で区別できない場合は類似候補を残し、無理に自動確定しない。候補外の正解がある場合も、推論値や判定成功を偽装しない。
- モデル候補、補助候補、位置根拠、採用された選択とそれぞれの由来を保存・再読込できること。候補の追加や並べ替えによる性能の改善・悪化は、同一入力で前後を比較して実測する。

## 入力と出力

- 入力: 同一数式の画群、認識モデルの記号候補とスコア、候補と画の対応、各画の元座標から求めた候補ごとの矩形。入力の座標原点・軸方向・単位・パッド範囲・仕様バージョンを明示し、前処理・推論・判定での一致を検証する。
- 幾何情報: 対象と周囲の矩形中心の相対距離、幅・高さ・比率、重なり、対象線の長さおよび上下左右の配置。平行移動に依存せず、同一式の尺度に対する相対値を用いる。ゼロ寸法や欠損は明示的に扱い、偽の値や候補を作らない。
- 出力: 記号候補と対象間の関係候補、判定に用いた根拠、確定・未確定状態。曖昧な横線は周辺関係を合わせて判定し、根拠不足なら未確定として利用者が選択する。
- 成果物: 入力仕様とルール版、記号認識モデルの識別子、入力の元座標・候補と画の対応、判定根拠、ユーザーが確定した構造、検証結果、導出結果と編集履歴。アプリの永続成果物は User Setting Root に保存し、再読込・編集できるようにする。

## 判定順序

1. 記号認識モデルが画の形から候補を返す。変換後の特徴とは別に、元の座標と候補の画対応を保持する。
2. 活字字形距離による候補とモデル候補を由来別に提示し、距離指標を混ぜない。`HinotoriManualSpatialClassification.md` は位置・構造関係を調べる優先度にだけ用い、活字類似度の正解ラベルとしては使わない。C群の記号も上付き・下付き等の構造関係から除外しない。
3. 横線に対して、候補の左右の式、上下の領域、線と周囲の幅・高さを確認し、マイナス・分数線・下線の候補を構成する。線の長さ単独では確定しない。比較する相手や上下の領域が不足・競合する場合は候補を残す。
4. 記号対について、相対的な右上・右下の位置と大きさ、対応する基底候補を調べ、上付き・下付き等の関係候補を構成する。隣接順や3×3領域の行だけで確定しない。複数の基底候補が競合する場合は未確定とする。
5. 競合・不確実な候補はユーザーに提示し、確定後の数式構造を検証する。保存が成功する前に完成した成果物として表示しない。入力不整合・保存失敗は理由と復旧操作を表示し、既存の検証済み成果物を保持する。

条件・閾値・判定優先順は未確定であり、実データで検証してから決定する。便宜的な閾値、固定の正解、黙った代替経路を実装しない。

## 検証

直接対応づけできた画群・記号・AST関係を、利用可能な正解根拠として監査する。数式LaTeXだけを根拠に画群への対応を捏造しない。ルールの設計・調整に使うデータと最終評価は元の数式ID単位で分離し、同一数式を跨がせない。書き手の特定は行わない。記号候補が誤っているケースも含む別の評価を用意する。

既存の `cycle391-three-layer-teachers/report.json` は直接AST対応4,317件（学習3,822・検証495）を記録し、`cycle392-instance-relation-contract-audit.json` は対応する正例286ペア・複数ラベルの曖昧9ペアを記録する。これらは現行モデルに使用できる保証ではなく、ID・座標・分類対象・分割・漏洩の再検証が必要。既存関係ヘッドは埋め込みを入力としており、要求された元の座標に基づく特徴の提供を確認できていない。

既存ペアの正例内訳は学習 baseline 173、radicand 35、numerator 28、denominator 27、検証 baseline 20、radicand 1、numerator 2、denominator 0。上付き・下付きの正例はこの集計にはない。ASTに直接辺がないことは位置関係がないことを意味しないため、既存の `none` を真の負例とみなさない。追加教師の根拠と対象ごとの実測が必要。

候補生成が正しい条件と実際の候補生成を接続した条件を分け、関係別の件数、再現率、精度、混同行列、未確定率、および式全体の構造正解率を測定する。横線の区別、上付き・下付き、入れ子、移動・縮尺、手書きの揺れ、曖昧入力の選択、保存・再読込・失敗復旧を検証する。欠損クラスは評価不能とする。
