# 歴史記録: 手書き数式認識モデル設計（2026-09-27）

> この文書は歴史記録です。現行の正本は `HandwrittenFormulaRecognitionDesign.md` です。

## 目的

MathWriting の数式全体データを入力し、対応する数式ラベルを出力する。入力を人為的に単記号へ切り出して別分類器を作らない。

```text
MathWriting train の数式全体
→ 入力列の正規化
→ 数式全体モデル
→ 文字・記号列と構造を含む正解ラベル
→ 検証済み MathML
→ User Setting Root へ保存・再読込
```

## 正本データ

正本は `/Volumes/ORICO/Developer/inf6-training/dataset/mathwriting-2024` とする。

| 分割 | 件数 | 用途 |
|---|---:|---|
| `train` | 229,864 | 学習 |
| `valid` | 15,674 | 検証・モデル選択 |
| `test` | 7,644 | 最終評価のみ |

`symbols` は個別記号へ抽出されたサブセットであり、このモデルの学習入力には使用しない。`synthetic` も、train の代替や補助教師として混ぜない。元の分割を維持し、`test` を学習・閾値調整・モデル選択に使用しない。

## 教師データ

各 `train/*.inkml` は画像ではなく、数式全体を表す InkML である。1ファイルを1つの学習例として扱う。

- `trace`: 数式全体を構成する座標列。trace間の境界と順序を保持する。
- `label`: 対応する数式ラベル。
- `normalizedLabel`: 正規化済みの正解数式ラベル。

教師データに文字ごとの切り出し境界がない場合、境界を人為的に生成しない。モデルは、数式全体の入力と文字・記号列ラベルの対応から、文字・記号への分解、順序、上付き・下付き・分数などの構造を学習する。

## 入力契約

### 学習側

InkMLから、各traceの座標列を読み込む。traceを結合して1本の文字列入力にせず、trace境界、trace順、点順を保持する。

学習前処理で固定する項目は次のとおりとする。

- 座標原点、軸方向、単位
- 座標の正規化範囲
- trace境界とtrace順
- 点列の再サンプリング規則
- 欠損値・空trace・非有限値の扱い
- dtype、shape、仕様バージョン

```text
FormulaInput v1
  traces: [
    [{x, y, optional t}, ...],
    ...
  ]
  traceOrder: [0, 1, ...]
  specVersion: "inf6-formula-input-v1"
```

学習側に存在しない情報を推論側だけで追加しない。筆圧、線幅、端末固有値を使う場合は、train側にも同じ情報が存在することを確認し、入力契約へ明記する。

### 数式パッド側

数式パッドの `PKDrawing` は、数式全体のすべての `PKStroke` を書かれた順に走査し、各strokeの点列を `FormulaInput v1` へ変換する。

```text
PKDrawing
→ 全PKStrokeを保持
→ 各PKStroke.pathの点列を座標正規化
→ trace境界・順序を保持
→ FormulaInput v1
→ 数式全体モデル
```

数式パッド側で3×3セル、記号グループ、記号bbox、個別記号分類を先に生成してはならない。これらは入力を単記号へ分解する補助経路であり、本モデルの入力契約に含めない。

## モデル構成

数式全体を入力し、文字・記号列を出力する単一の数式認識モデルを基本構成とする。

```text
FormulaInput v1
→ trace encoder
→ sequence / structure decoder
→ normalizedLabel のトークン列
→ LaTeX / MathML
```

モデルは次を一体の学習対象として扱う。

- 文字・記号の認識
- 文字・記号の境界と順序
- 上付き・下付き
- 分数の分子・分母
- 根号の作用域
- 行列・積分・総和などの構造
- 数式列の終了位置

独立した `HandwrittenSymbolClassifier`、`StrokeGrouping`、`FormulaRelationClassifier` は作成しない。9セルによる固定位置判定、単記号Gaussian／prototype分類、synthetic由来の補助分類器も作成しない。

## 学習

1. `train` の各InkMLを1例として読み込む。
2. trace境界・順序を保持した `FormulaInput v1` を生成する。
3. `normalizedLabel` をトークン列へ変換する。
4. 数式全体の入力から、ラベルの文字・記号列を直接学習する。
5. `valid` でモデル設定、語彙、終了条件を選択する。
6. `test` を最後に一度だけ実行し、文字列完全一致、編集距離、構造一致、MathML一致を測定する。

文字単位の教師データがない場合、文字境界の教師を推測して追加しない。sequence-to-sequenceまたは同等のアライメント機構で、数式全体ラベルとの対応から潜在的な分解を学習する。

## 出力と検証

モデル出力は、推測した説明文ではなく、元ラベルに対応する検証可能な数式列でなければならない。

検証項目:

- 出力トークンが許可語彙に含まれる
- 終了条件が成立している
- 括弧、分数、根号、添字、指数の構造が整合する
- LaTeXからMathMLへの変換が成功する
- MathMLの構造検証が成功する
- 入力、出力、モデルバージョン、評価結果を保存できる

検証失敗時は、未検証の数式を成功扱いで保存しない。失敗工程と原因を表示し、直前の検証済み成果物を保持する。

## Core ML化

Core ML化する成果物は、数式全体を入力する単一モデルとする。

```text
FormulaRecognizer.mlpackage
```

変換前後で、同一の `FormulaInput v1` を与え、入力shape、dtype、値域、出力shape、終了条件、トークン列、MathML、数式完全一致率、編集距離を比較する。

一致しないモデルはアプリへ組み込まない。単記号モデルを組み合わせて数式全体モデルの代用にしない。

## 完成条件

次のすべてを満たすまで完成扱いにしない。

- `train` の数式全体データから学習している
- `symbols` の抽出記号データを学習入力にしていない
- 数式パッドの全PKStrokeを `FormulaInput v1` へ変換できる
- 学習側と推論側の入力契約が一致する
- 文字・記号への分解と順序を数式全体ラベルから学習している
- `valid` と `test` の分離が監査できる
- Core ML変換前後の出力が一致する
- 実際の数式パッド入力からMathMLを生成できる
- 検証済みMathMLをUser Setting Rootへ保存し、再読込できる
- 未検証・未実装・未測定を完成と表現していない
