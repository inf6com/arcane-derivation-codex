# Hinotori 画群分割の推移性監査

対象: `hinotori_group_proposer.py` の `decode_groups` と `HinotoriCoreMLContract.md`。設計上の性質の確認であり、認識精度の実測ではない。

## 確認結果

有効な画のペアの logit が 0 を超えると辺を結び、連結成分を一つの記号群にする。この操作は、辺が直接存在しない画同士も、間に経路があれば同一群にする。

例えば、3画 A・B・C で A–B と B–C の logit が正、A–C の logit が負の場合、出力は `{A, B, C}` 一群になる。これは実装から導ける結果であり、学習データでこの誤結合が発生したことや、その頻度を意味しない。A・B が一記号、C が別記号という正解の場合は、B–C の正の辺一つが両記号の結合を引き起こす。

## 改善に必要な検証

直接教師で画と記号の対応が検証された数式について、実際の affinity logit、正解画群、数式ID、チェックポイントと入力仕様を固定して保存し、以下を集計する。ルール調整と最終評価には別の数式IDを使用する。

- 予測一群に複数の正解群が含まれる過結合と、一つの正解群が複数の予測群に分かれる過分割を別々に数える。
- 過結合のうち、正解群間の正の辺を取り除くと群が分離するケースと、その辺の logit を調べる。辺の削除は診断に限り、正解を推論時に利用しない。
- 群の完全一致率、記号候補 Top1/Top5、数式単位の構造正解率を別々に評価する。教師がない構造関係は評価不能とする。
- 改良候補は同じ checkpoint・入力・分割条件で比較し、Swift とモデル変換後も同じ分割契約を実装する。数値・計算量の改善は測定まで主張しない。

この監査だけでは代替分割規則の正当性を決められない。閾値や規則を推測で変更せず、実データの誤結合内訳を先に取得する。ビルドは行わない。
