## 1. 現行推論経路

入力は通常チャット欄へ描かれた数式全体のPKDrawingです。式全体のbbox中心と最大辺で一様正規化し、ストローク順を維持して各ストロークを弧長32点へ再標本化します。分割器は80×80の対称affinity logitを出し、平均リンク階層クラスタリングで群間平均logitが-1.0を超える間だけ群を統合します。現行Fold07 checkpointはepoch 33、inner-validation選定閾値-1.0です。切り捨てやGrid9による分割はしません。

各候補群をFold7の孤立記号229分類器へ渡し、Top-5の元logit・クラス距離を得ます。次に類似87群の候補追加、その後に位置ルールを別段として適用します。元ストロークインデックスから各候補群への対応を保持します。分割は候補であり、MathML検証・利用者確定までチャット本文にコミットしません。空入力、不正座標、80ストローク超過、欠落資産、モデル形状不一致、推論失敗は具体的なエラーにします。

旧epoch 38 checkpointでは、連結成分閾値1.0と平均リンク閾値1.25がともに33/61式完全一致でした。平均リンクのpair F1は0.806（precision 0.724、recall 0.909）で、連結成分の0.671より高かったためdecoder方式を採用しました。その後、重み・損失候補をinner validationだけで選び、epoch 33候補は34/61式完全一致、pair F1 0.788（precision 0.680、recall 0.937）でした。方式比較と候補選定はいずれも同じinner validation値を含みます。

旧epoch 38・閾値1.25の内側検証誤り内訳は完全一致33式、誤併合のみ16式、誤分割のみ5式、両方7式です。固定したepoch 33候補をsource-disjoint outer holdoutで一度評価し、群教師が有効な132式中75式が完全一致しました。外側評価の誤併合のみ34式、誤分割のみ15式、両方8式で、pair F1は0.730です。外側評価後の変更をこのholdoutで再評価して独立値とは呼びません。

一記号内の線の書き方向やストローク配列順を正解ラベルとして扱いません。左利き・右利きで線の向きや画順が異なる例を含むsource-disjointデータで、その差に対する性能を別途測ります。未検証の方向不変性を達成済みとは記しません。

現行の完成条件は、直接教師のsource-disjointデータでのTop-1/Top-5、macro recall、記号別誤答・誤認ペア、類似候補距離の評価と、位置規則の適用前後比較です。Top-1/Top-5は229記号の厳密一致で算出し、類似記号を正解扱いして加点しません。

### 革新要件：iPad上のANEエッジ推論

火の鳥を「革新的な手書き記号モデル」として採用・評価するための必要条件に、対応する実機iPadのApple Neural Engine（ANE）上で学習済み認識グラフを実行することを置きます。ANE対応や端末内実行だけで革新性・優位性が証明されるわけではありません。モデル構造・評価性能・既存方式との差は独立して比較し、根拠が揃うまで新規性や世界順位を断定しません。

ANE合格には、Core MLの設定値やモデル読込成功ではなく、実機のCompute Planまたは同等の実測診断で認識グラフがANEへ配置・実行された証拠を保存します。CPU/GPUへ移った演算、未対応演算、失敗は明記し、ANE実行として数えません。固定した入力契約・評価分割・checkpointに対して、PyTorch基準との数値／候補一致、229クラス厳密Top-1/Top-5、遅延、ピークメモリ、エネルギーを計測します。類似距離・位置判定の前後も同一サンプルで比較し、端末上の総合結果を報告します。

学習時のMac MPS要件と、推論時のiPad ANE要件は別のゲートです。MPS利用不可を理由にCPU学習へ黙って切り替えず、ANE設定を実測せずにANE合格とも扱いません。現行Fold7分類器と分割器はCore ML資産としてアプリへ組み込み済みです。iPad実機での起動・ANE実行検証は未完了です。

### 書き方の違いと評価方針

利用者に特定の書き方向や画順を要求しません。左利き・右利きや個人の癖によって同じ記号の線を引く方向や画順が異なっても、同じ記号として認識することを目標とします。一方、見た目が似た別記号は区別する必要があります。

特徴量が書き方向や画順を保持するかどうかだけで、設計を良否判定しません。独立した評価データで、同じ記号の異なる書き方に対する認識率と、形の似た別記号の誤認率を確認します。書き方向や画順による差は、実際に条件を識別できるデータに限って比較し、未測定の場合は未検証と記録します。人手や実例による裏付けなしに、機械的な反転・並べ替えを自然な筆記例の代わりとせず、異なる記号を同一視しません。

現行の特徴変換は、一画の点ごとの特徴を最大値で集約するため、その一画の点順序を保持しません。一方、画ごとの特徴はGRUに順番に渡されるため、複数画の順序に影響され得ます。これは実装上の性質であり、書き方の違いに対する認識性能の検証結果ではありません。

```text
一記号分のストローク群
 → 全229記号の候補スコア・順位
 → 類似記号の距離付き候補
 → 元座標に基づく独立の位置判定
 → 利用者が確定できる記号候補と判定根拠
```

## 2. 教師データの区分

現行学習・選択・評価の正解源は、MathWritingの一記号単位直接教師です。source formula単位でtrain/validation/outer-testを分離し、ストローク群と229ラベルの対応を保ちます。全数式のLaTeXから作る弱教師は現行モデルの学習、checkpoint選択、性能報告に使用しません。既存の弱教師実験データ・checkpointは履歴資産として保持します。

以下の旧テーブルと弱教師設計は、履歴記録であり現行契約ではありません。

| 教師 | 件数 | 含む情報 | 学習上の役割 |
|---|---:|---|---|
| 弱教師（全体） | 222,443式 | 数式全体のInkMLストロークと最終LaTeX | 229語彙へ完全対応するtrain/valid式。各式をLaTeX由来の記号多重集合として扱います。 |
| 弱教師 train | 207,924式 | 学習用InkMLストロークと最終LaTeX | 主教師。LaTeX由来の229記号多重集合を、単一共有モデルへ与えます。 |
| 直接教師 | 6,405記号 / 229種類 | 記号ごとのストローク集合と229ラベル | 補助教師。潜在所属と分類空間を補正し、検索根拠を与えます。 |
| valid | 15,674式 | 学習外のInkMLと最終LaTeX | モデル選択と評価だけに使います。 |

弱教師にもストロークがあります。不足しているのは、個々のストローク群と229記号の対応です。その対応を全20万件で人手付与するのではなく、弱教師の記号多重集合との一致からモデルが獲得します。

直接教師は全数式に必要な前提ではありません。少量の対応済み例により、弱教師だけで起こり得る記号の入替え、同形字の混同、所属確率の退化を補正します。

### 2.1 LaTeX由来229記号部分集合

最終LaTeXを固定229語彙の`visualSymbols`へ変換し、記号 `c` を少なくとも一度含む数式の集合を `W_c` と定義します。

```text
W_c = { formula | latexMultiset(formula)[c] >= 1 }
```

一つの複合数式は、含まれる全記号の `W_c` に所属します。これは記号ごとのストローク境界を意味せず、LaTeXが保証する数式レベルの所属だけを表します。

Hinotori語彙に対する部分集合成果物は `build_hinotori_subsets.py` が作成します。229個の`class-XXX.json`は、各記号の`split`と`sourceSampleId`を決定的順序で保存し、`manifest.json`は語彙ハッシュ、対象式数、除外数、各部分集合のハッシュを保存します。

部分集合は、カバレッジ監査とクラス平衡な**サンプリング**に使います。記号ごとに別モデルを作ること、ある記号の重みを次の記号へ引き継ぐこと、1対その他の二値分類器を作ることには使いません。

### 2.2 部分集合と直接教師を一つの共有モデルへ統合する方法

学習単位は、対象記号 `c`、弱教師部分集合から選んだ複合数式 `f ∈ W_c`、および同じ記号の直接教師 `a ∈ A_c` の組です。

```text
choose c uniformly from observed 229 classes
choose f from W_c                 # LaTeXがcを含む複合数式
choose a from A_c                 # cの直接ストローク教師

候補生成:
  formula f の各潜在ストローク群 q_j を、全直接教師 A と照合する
  A_c       : q_j が記号cである候補
  A \ A_c   : q_j が式の残りの記号である候補

shared model update:
  L_present(f,c) = A_c に近い潜在群が少なくとも一つある損失
  L_formula(f) = A_c と A \ A_c の全候補を使う229次元LaTeX多重集合損失
  L_anchor(a)  = aがA_cへ近く、A \ A_cから離れる直接教師検索損失
  L_group(a)   = aの既知ストローク所属による分離補助損失
  L = L_present(f,c) + L_formula(f) + λ_anchor L_anchor(a) + λ_group L_group(a)
```

`A_c` は正例候補、`A \ A_c` は残余記号の候補であり、別モデルではありません。各潜在群は全候補と比較し、最終LaTeXの完全な多重集合に対する一対一でない最適輸送割当が、`c`以外の必要個数を `A \ A_c` へ配分します。弱教師は「どの群がcか」を与えないため、残余群へ直接ラベルを捏造しません。`c`はサンプルを選ぶための索引であり、出力次元を`c`だけに制限しません。`f`に含まれる全記号のカウントを`L_formula`で照合し、`L_anchor`も検索バンクにある全229クラスとの比較で計算します。一回の更新は一つの共有エンコーダ、共有所属層、共有229候補空間を更新します。

同じ複合数式が`W_c`と`W_d`の双方に属する場合、`c`の直接教師との組と`d`の直接教師との組で別の更新に現れます。これは誤った重複教師ではありません。同一数式の完全なLaTeX多重集合を保ったまま、各記号の直接形状を対応付けるための反復です。

弱教師部分集合が空のクラスも、最初の229クラス巡回に`row = -1`の直接教師更新を一回入れます。したがって`\\vdots`のように`W_c`が空のクラスを、全弱教師更新の末尾まで遅延させません。これは弱教師を捏造せず、存在する直接教師だけで共有エンコーダ・所属層・229候補空間を更新する扱いです。

## 4. 旧実験モデルの実装記録（現行仕様ではない）

### 4.1 現行コードの実装事実と設計差分

現行実装は各ストロークを `TrajectoryGroupEncoder` で埋め込み、`StrokePairAffinity` がストローク対の同一記号logitを出力します。`decode_groups` は `logit > 0` の辺を連結成分へまとめ、離散的なストローク群を作ります。これは連続所属確率をインスタンス表現へ伝播する方式ではありません。

`direct_grouping_loss` は直接教師の群ラベルから所属器を学習します。一方 `formula_retrieval_logits` はaffinityを `detach()` して離散群を作るため、`weak_formula_loss` と `weak_class_presence_loss` の勾配は所属器へ戻りません。弱教師は提案された群の検索表現を更新し、所属器の教師にはなっていません。

したがって、以前の「弱教師損失がストローク所属層まで逆伝播する」「連続所属確率を計算する」という記述は現行コードに対して誤りです。現行方式を採用する場合は、直接教師だけで学習される群提案器の独立したsource-disjoint群分割評価が必要です。弱教師から群提案器も学ばせる設計へ変更する場合は、離散decodeを通らず勾配が届く目的関数・群表現を別途定義し、改変した学習を旧チェックポイントの継続学習と混同してはなりません。

### 4.2 229分類と検索根拠

各潜在記号インスタンスを全直接実例の検索バンクと比較します。各クラスは一実例に圧縮せず、全変種を使用します。

```text
score(c | instance) = logsumexp(similarity(instance, directExample_i) / temperature)
```

推論結果には、229クラス候補のlogit、特徴距離、根拠となった直接実例IDを保存します。logitや距離を、校正されていない確率・信頼度として表示しません。

### 4.3 活字画像と手書き直接教師による類似部分集合

類似部分集合は、LaTeX名の文字列比較、Chamfer距離、画素距離、埋め込み距離、手書きFold分類器の流用では作らない。語彙を Unicode に単独の実字形があるラベルと、単独 Unicode 文字を持たない数式構造コマンドに分ける。

#### Unicode字形

英字、ギリシャ文字、数字、演算記号、Unicode数学英数字（二重線文字など）は、正規のUnicode対応表で符号位置を確定し、Macにインストールされた全フォントを列挙して、該当字形を収録するフォントから画像標本を描画する。フォントファイルはローカルで読み取り、複製・再配布しない。フォント別の収録有無、フォント識別子、描画条件、Unicode対応表と各画像のハッシュを記録する。フォントによって字形を持たない場合は、そのフォントでの非収録として記録する。Mac内の全フォントで非収録のUnicode字形も229ラベルの分類対象から外さず、補助フォントとしてライセンスを確認したSTIX Two Mathなど、字形を収録する数学フォントの画像を明示的に追加する。Unicode scalar自体がないラベルは構造コマンド画像系統へ割り当てる。画像根拠を作れない項目を無根拠に類似群へ入れず、類似根拠なしの単独集合として明示する。

ViT画像分類器を、各ラベルのフォント間字形変化を学ぶように訓練する。評価時はフォントファイル単位で分離した保留フォントと、sourceSampleIdで分離したMathWritingの手書き直接教師を別ドメインとして測る。手書き集合生成にはfit側の直接教師画像のみを使い、inner validationとouter testは使わない。いずれかのドメインでA→BとB→Aが各2件以上かつ両方向の誤認率が10%以上の場合だけ、無向の類似部分集合に同居させる。ドメインごとの件数・分母・率を記録する。強い辺から完全連結条件で集合を併合し、全ての異なるペアに直接の相互誤認根拠がない推移的結合を禁止する。

#### 単独Unicode字形がない構造コマンド

`\frac`、`\overline`、`\underline`、`\hat`、`\tilde`、`\vec` などを既存の別文字へ置換せず、コマンド名から字形を作らない。引数を含む正規数式を定義し、Macのフォントと数式組版で画像を描画する。構造数式画像はUnicode一字形と別のラベル種別としてViTで扱い、保留フォント上の構造コマンド間混同だけを構造集合へ反映する。数式構造の誤認を孤立字形の誤認と混ぜない。

#### 成果物・採否

229語彙の各ラベルに `unicode-glyph` または `math-structure` を付け、全件を一度ずつ成果物へ含める。Unicode字形には符号位置とMac全フォントでの収録状況を、構造コマンドには正規数式・引数構造・組版条件を記録する。ViTの学習/保留フォント分割、手書き直接教師のsource split、画像・語彙・フォント一覧・教師のハッシュ、ドメイン別混同行列、相互混同から得た類似部分集合、どの集合にも入らない単独ラベルを保存する。画像カバレッジまたは保留画像評価の不足は成功扱いにせず、欠落ラベルと件数を出す。

活字と手書きの予測率は別々に保存し、学習側手書き画像上の率を独立性能と呼ばない。候補を追加する本番評価は、sourceを分離したFold7 inner validationで行い、outer testは設計選択後の最終評価まで未使用とする。手書き推論では類似段を位置判定より前に別処理として適用し、元のモデル順位・候補由来を保持する。類似ラベルを統合せず、最終選択は利用者が確定する。

STIX Two Mathの補助利用は、STIX Fonts公式サイトが示すSIL Open Font License 1.1の条件内に限定し、フォントファイルとライセンス文を一緒に保持する。Mac標準フォントは調査・標本生成のローカル利用に限り、アプリや成果物へ再配布しない。

### 4.4 弱教師主損失

各式の潜在記号インスタンスの229確率を有効確率で重み付けして合計し、LaTeX由来の229記号多重集合と照合します。

```text
predictedCount[c] = Σ instanceActive[j] × P(c | instance_j)
L_weak = transport/count loss(predictedCount, latexMultisetCount)
```

各最適化ステップは、選ばれた一式の**全229次元**の多重集合を同時に照合します。あるクラスがその式のLaTeXに無ければ、その多重集合カウントがゼロであること自体が数式レベルの負例です。別の二値不在損失やクラス別のチェックポイント連鎖は追加しません。

クラス平衡なサンプラは229部分集合を巡回して式を選んでも、選んだ式の完全な229次元ターゲットを失いません。従って`\\sqrt`を含む式を選んだ場合も、同時に現れる`x`、添字、演算子などを含む複合教師として更新します。

### 4.5 直接教師補助損失

```text
L_direct(c) = same-symbol membership loss from direct examples A_c
            + 229-way retrieval loss for direct examples A_c
L = L_weak(f) + λ × L_direct(c)
```

直接教師では、同じ記号に属するストローク対と異なる記号に属する対を監督します。これにより弱教師で潜在的に同じ個数を満たすだけの誤分離を抑えます。検索時の候補バンクと負例候補は常に全229クラスから取り、対象`c`以外を無視しません。弱教師部分集合が空の`\\vdots`は、現時点では33件の直接教師だけで学習可能な状態として記録し、弱教師があると偽装しません。

## 5. 旧実験の左から右への出力（現行仕様ではない）

学習後、所属確率から確定した記号インスタンスを得ます。各インスタンスのx中心を昇順にして出力します。これは読取り順だけを定める処理であり、書込み順、trace ID、固定セル、固定矩形を使用しません。

確定できないインスタンスは未確定ストロークとして残し、記号を捏造して消費しません。

## 6. 現行の評価条件

### 6.1 入力境界・データ分割・指標

一件の評価入力は、直接教師で記号境界と正解229ラベルが与えられた一記号分のストローク群です。数式全体の自動記号分割、記号列の順序、LaTeX/MathML式完全一致は測定しません。分割は必ずsource formula単位とし、同じsourceの記号をtrain/validation/testへ分散させません。現行fold-05はfit-train 5,455記号/3,061 source、inner validation 450/155 source、未使用outer test 500/209 sourceでsource overlapは0、outer testに出現したクラスは227/229です。

Top-1/Top-5は229ラベルの厳密一致です。活字字形距離や学習特徴距離が近い候補でも完全一致では正解に数えません。字形距離順位と学習特徴距離順位は独立した診断値として報告します。macro recallはtestに実際に出現したクラスで算出し、標本がないクラスを正解扱いしません。

checkpointと融合の選択はinner validationだけで行い、outer testは全候補を固定して一度だけ評価します。評価済みtestを使った後続変更は、同じtestで再評価して最終値と称しません。類似ペア、距離境界、位置規則をtest誤答から作りません。

報告する比較は (1) 形状モデルの229-way Top-1/Top-5、(2) 類似候補・距離順位を加えた後の厳密Top-1/Top-5と類似群別recall、(3) 座標位置規則を別途加えた後の同じ値です。各段階で、同じ一記号入力・同じsource-disjoint split・元座標・候補・判定根拠を保持します。これは孤立記号分類の評価であり、数式全体認識を意味しません。

| 評価 | 対象 |
|---|---|
| 形状のみ | 一記号あたり229-way厳密Top-1/Top-5、macro recall、誤答ペア |
| 類似段階 | 同一記号の厳密Top-1/Top-5、活字字形IoU/Chamfer順位、学習特徴距離順位 |
| 位置段階 | 同一一記号例の位置適用前後Top-1/Top-5、誤答ペアの増減 |
| 根拠 | 各候補の直接教師距離・候補出所・座標・適用した規則 |
| Python/Swift parity | 同じ孤立記号ストローク入力で候補・順位・距離が一致すること |

合格値はvalidの実測後に固定します。未実装、未測定、弱教師との個数一致だけを完成と表現しません。

チェックポイントを使ったすべての評価は、評価した重みファイル自体とSHA-256をレポートの隣に保存します。評価レポートだけが残り、重みが失われた測定値は再現不能として明示し、変換・採用根拠に使いません。

## 7. 保存と失敗復旧

保存対象は、一記号分の入力ストロークと元座標、229候補スコア、類似距離、位置判定根拠、確定ラベル、モデル・語彙・入力契約の版、検証結果です。数式全体の分割結果・記号列は現行モデルの成果物に含めません。User Setting Rootへの保存・再読込はアプリ側統合で別途検証します。

失敗時は、未確定ストロークと具体的な失敗理由を保持します。旧の全数式モデル、書込み順規則、固定矩形規則、擬似成功への迂回は行いません。
